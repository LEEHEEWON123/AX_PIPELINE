# AX 안내서 규격

원본 기준: CRM "성장·유지 관리 사용 안내서".
템플릿: `template.html`

## 원칙

**독자는 현업이다.** 마케터·팀장·본부장이 읽는다. 개발자가 아니다.

- 엔드포인트·컴포넌트·테이블 이름을 쓰지 않는다
- 화면에 실제로 적힌 말을 그대로 쓴다
- "무엇이 생겼나"로 시작한다. 기능 목록이 아니라 이전에 무엇이 불편했고 이제 무엇이 되는가

원본의 이 문장이 기준선이다 — *"마케터가 새로 배워야 할 것은 거의 없습니다. 달라지는 동작은 딱 두 가지입니다."*

## 구조

```
좌측 고정 목차 (그룹 라벨: 화면 / 숫자 읽는 법 / 운영)
헤더 — eyebrow(모듈명) + h1 + lede + meta(대상·화면·기준·캡처)
본문 섹션들
푸터
```

## 섹션 요소

### 개발항목 태그 칩

섹션 제목 옆에 `<span class="tag">선택-6</span>`. Total PRD로 역추적되는 고리다. **빠뜨리면 추적이 끊긴다.**

### 캡처 + 번호 핀

```html
<figure class="shot">
  <div class="frame">
    <img src="shots/ac-1-account-view.png">
    <span class="pin" style="left:23%;top:41%">1</span>
  </div>
  <figcaption>계정 성장 뷰 — 계약 정보 영역</figcaption>
</figure>
<ol class="legend">
  <li><b>회차</b> 지금 몇 번째 계약인지<span class="note">갱신할 때마다 1씩 오른다</span></li>
</ol>
```

핀 번호와 legend 순번은 **1:1로 맞는다.** 어긋나면 문서가 무너진다.
핀 좌표는 캡처를 실제로 보고 정한다. 짐작하지 않는다.

### 추적표

개발항목 ↔ 확인 위치. 화면 없는 항목(공통-1~4 등)은 "다른 화면의 어느 값으로 나타나는가"를 적는다.

### 콜아웃

`.note-box` 기본 / `.warn` 주의 / `.stop` 경고. 남발하지 않는다.

### 절차

`ol.steps`. 사용자가 순서대로 눌러야 하는 것에만 쓴다.

## 반드시 다루는 것

- **빈 값일 때 어떻게 보이는가** — 현업이 가장 많이 묻는다. 원본에도 "비어 보이는 값" 절이 따로 있다
- **평소에 할 일** — 일상 운영에서 무엇을 하면 되는가
- **확인이 남은 항목** — 아직 미정인 것을 숨기지 않는다

## 기술 규격

- 라이트/다크 양쪽. `:root` 토큰 → `@media (prefers-color-scheme:dark)` + `:root[data-theme="dark"]` 3중 정의
- 한글 폰트: Gothic A1(제목) / IBM Plex Sans KR(본문) / IBM Plex Mono(숫자·코드)
- 표는 `.tw` 래퍼로 감싸 가로 스크롤. 페이지 자체는 가로로 흐르지 않는다
- 인쇄 스타일 포함 — 출력해서 보는 사람이 있다
- 이미지는 data URI로 인라인. Artifact는 외부 호스트를 막는다
